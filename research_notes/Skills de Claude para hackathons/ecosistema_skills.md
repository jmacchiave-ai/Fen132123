# Ecosistema de Claude Agent Skills y plugins de Claude Code (estado al 26-oct-2026): fuentes, confianza, catálogo para la hackathon e instalación en Windows

Nota de método: todas las cifras de estrellas/forks se leyeron de las páginas de GitHub el 26-oct-2026 vía fetch. En la mayoría de los repos GitHub no mostró la fecha del último commit en el texto capturado; se indica cuando sí se pudo ver. También se revisó (solo lectura) el equipo del usuario: `claude` CLI **no** está en el PATH, `git` sí (C:\Program Files\Git), `node` **no** está en el PATH, Python 3.13 sí. Ya hay 19 skills en `~/.claude/skills` y 5 skills de proyecto propias en `Tech Hack\.claude\skills` (analizar-desafio, defensa-jurado, negocio-e-impacto, pitch-ganador, prototipo-express).

## 1. Fuentes oficiales de Anthropic (qué son, qué contienen, nombres exactos)

### Takeaway
Anthropic mantiene tres fuentes oficiales relevantes: `anthropics/skills` (marketplace `anthropic-agent-skills`, 19 skills), `anthropics/claude-plugins-official` (marketplace `claude-plugins-official`, viene preinstalado y agrega cientos de plugins de Anthropic y partners, incluidos superpowers, mattpocock-skills, frontend-design, playwright y playground) y `anthropics/knowledge-work-plugins` (11 plugins por rol: product-management, marketing, sales, data, etc.). Para esta hackathon, lo más útil y confiable de Anthropic es: frontend-design, webapp-testing, theme-factory, doc-coauthoring, canvas-design, discernment-nudge (skills); product-management y marketing (knowledge-work); playground y playwright (official).

### Inferences
- Muchas de las skills ya instaladas (design-taste-frontend, impeccable, high-end-visual-design, ui-ux-pro-max) se solapan con **frontend-design** de Anthropic; igual vale la pena tenerla porque es la referencia oficial y la más usada del ecosistema, pero puede competir en el "trigger" con las otras. **theme-factory** se solapa parcialmente con brand/brandkit/design-system.
- `web-artifacts-builder` probablemente no es práctica en este equipo hoy (requiere Node 18+ y bash; Node no está en el PATH). Para prototipos de un solo HTML, el flujo actual (prototipo-express + Artifact) o `playground` es más simple.
- `discernment-nudge` es útil para entrenar pensamiento crítico del equipo (no programadores) antes de decidir: obliga a verificar supuestos y cifras.
- `document-skills` (docx/pptx/pdf/xlsx) ya está cubierto por los built-ins del usuario; no instalarlo de nuevo para evitar duplicados.

## 4. Cómo instalar skills y plugins en Claude Code (y qué funciona en la app de escritorio, pestaña Code, en Windows)

### Takeaway
Hay cuatro vías: (a) copiar la carpeta de la skill (con su `SKILL.md`) a `~/.claude/skills/<nombre>/` (personal) o `<proyecto>\.claude\skills\<nombre>\` (proyecto) — se recarga en vivo, sin CLI; (b) en la app de escritorio, botón **+** junto al prompt → **Add plugins** (o Plugins → Browse plugins) para instalar desde los marketplaces registrados y elegir scope; (c) comandos de sesión `/plugin marketplace add …` y `/plugin install …@…`; (d) comandos de shell `claude plugin marketplace add` / `claude plugin install` (no interactivos). En este PC el CLI `claude` no está en el PATH, así que la vía (d) no funciona tal cual; la vía (a) con `git clone` sí (git está instalado). Las skills subidas a claude.ai (ZIP) no se sincronizan solas con Claude Code local, salvo los plugins/skills activados en la cuenta que llegan por "sync".

### Cited Findings
**Ubicaciones y comportamiento de skills**
- Personal: `~/.claude/skills/<name>/SKILL.md` (todos los proyectos); Proyecto: `.claude/skills/<name>/SKILL.md` (este repo); Plugin: `<plugin>/skills/<name>/SKILL.md`, invocada como `/plugin-name:skill-name`; precedencia enterprise > personal > proyecto; las de plugin tienen namespace y no colisionan — [Docs: Skills](https://code.claude.com/docs/en/skills)
- Instalación manual: copiar la carpeta con `SKILL.md` a un directorio de skills; Claude Code vigila esos directorios y aplica cambios en la sesión actual sin reiniciar (excepción: si se crea un directorio `skills/` de nivel superior que no existía al inicio, ejecutar `/reload-skills`) — [Docs: Skills](https://code.claude.com/docs/en/skills)
- Invocación: `/nombre-skill` o automática cuando la `description` coincide; `/skills` lista las disponibles — [Docs: Skills](https://code.claude.com/docs/en/skills)
- Windows: `shell: bash` en una skill requiere Git Bash; `shell: powershell` usa la herramienta PowerShell — [Docs: Skills](https://code.claude.com/docs/en/skills)

**Plugins: comandos**
- En sesión: `/plugin install commit-commands@claude-plugins-official` abre el panel con detalles ("Will install", "Last updated", "Context cost") y luego se elige scope: user (`~/.claude/settings.json`), project (`.claude/settings.json`, se commitea) o local (`.claude/settings.local.json`); `/plugin` sin argumentos abre Discover; tras instalar puede pedir `/reload-plugins` — [Docs: Install plugins](https://code.claude.com/docs/en/discover-plugins)
- Agregar marketplace: `/plugin marketplace add owner/repo` (GitHub; `#ref` para fijar rama/tag), URL git completa con `https://`, ruta local (`./…`) o URL a `marketplace.json`; `/plugin market` es atajo. Agregar e instalar en un paso: `/plugin install <plugin> --marketplace owner/repo` (Claude Code ≥ v2.1.275) — [Docs: Install plugins](https://code.claude.com/docs/en/discover-plugins)
- Desde shell (no interactivo): `claude plugin marketplace add anthropics/claude-plugins-official`, `claude plugin install <name>@<marketplace> [--scope project|local]`, `claude plugin install <plugin> --marketplace owner/repo` (≥ v2.1.292), `claude plugin list`, `enable`, `disable`, `uninstall`, `update`, `details`; `--yes` para aceptar fuentes tipo `command` en scripts. - La terminal, las sesiones locales de la app de escritorio y VS Code en el mismo PC leen los mismos archivos de settings: un plugin instalado a nivel user en uno está disponible en los otros — [Docs: Install plugins](https://code.claude.com/docs/en/discover-plugins)

**App de escritorio (pestaña Code) y Windows**

## 5. Seguridad: riesgos documentados de skills de terceros, guía de Anthropic y checklist de verificación

### Takeaway
Anthropic indica usar skills "only from trusted sources: those you created yourself or obtained from Anthropic", y que un plugin "can execute arbitrary code on your machine with your user privileges". La evidencia 2026 es seria: Snyk (feb-2026) encontró fallas en 36.8% de 3,984 skills de ClawHub y skills.sh y 76 maliciosas confirmadas; un estudio académico confirmó 157 maliciosas entre ~98k. El riesgo concreto son instrucciones ocultas (prompt injection), comandos ofuscados, descargas remotas y robo de credenciales; las skills de solo Markdown de autores reconocidos son de bajo riesgo, pero siempre hay que leerlas.

### Cited Findings
**Guía oficial de Anthropic**
- "Use Skills only from trusted sources: those you created yourself or obtained from Anthropic." Una skill maliciosa puede dirigir a Claude a llamar herramientas o ejecutar código de forma distinta a su propósito declarado; puede llevar a exfiltración de datos o acceso no autorizado. Recomendaciones: auditar todos los archivos (SKILL.md, scripts, imágenes, recursos), buscar llamadas de red inesperadas o accesos a archivos que no calcen con el propósito; las skills que traen datos de URLs externas son especialmente riesgosas (el contenido puede cambiar); tratar como instalar software — [Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)
- En Claude Code las skills tienen el mismo acceso a red que cualquier programa del usuario — [Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)
- "A Claude Code plugin you install can execute arbitrary code on your machine with your user privileges." Hooks, monitors, mods, servidores MCP/LSP y el directorio `bin/` corren con permisos completos del usuario y **fuera del sandbox**; skills/comandos/agentes entran al contexto como instrucciones; con auto-update los archivos revisados pueden cambiar — [Docs: Plugin security](https://code.claude.com/docs/en/plugins/security.md)
- Pasos oficiales de revisión: (1) `claude plugin marketplace list` para ver la fuente; (2) leer el panel "Will install"; (3) leer `hooks/hooks.json`, `.mcp.json` y todo `bin/`; (4) `claude --plugin-dir <dir> plugin details <name>` para inventario de componentes; para remover: `claude plugin uninstall <plugin> --scope …` y borrar caché en `~/.claude/plugins/cache/<marketplace>/<plugin>/` — [Docs: Plugin security](https://code.claude.com/docs/en/plugins/security.md)
- Riesgos específicos en skills: `allowed-tools` no está limitado por la confianza del workspace (las pre-aprobaciones aplican aun en carpetas no confiables); las inyecciones `` !`comando` `` se ejecutan antes de que Claude vea la skill; `"disableSkillShellExecution": true` bloquea esas inyecciones; carpetas de skill con `.claude-plugin/plugin.json` pueden cargar hooks y MCP — [Docs: Skills](https://code.claude.com/docs/en/skills)
- Advertencia de confianza que muestra Claude Code: "Make sure you trust a plugin before installing, updating, or using it. Anthropic does not control what MCP servers, files, or other software are included in plugins…" — [Docs: Plugin security](https://code.claude.com/docs/en/plugins/security.md); [claude-plugins-official README](https://github.com/anthropics/claude-plugins-official)
- Anthropic no revisa marketplaces de terceros — [Docs: Anthropic's marketplaces](https://code.claude.com/docs/en/plugins/anthropic-marketplaces.md)

**Evidencia de ataques y estudios (2026)**
- Snyk ToxicSkills (5-feb-2026): 3,984 skills de ClawHub y skills.sh; 13.4% (534) con al menos un problema crítico; 36.82% (1,467) con alguna falla; 76 maliciosas confirmadas por revisión humana (8 seguían públicas en ClawHub); 100% de las maliciosas tenían código malicioso y 91% además prompt injection; secretos hardcodeados en 10.9% de ClawHub; 17.7% traen contenido de terceros; 2.9% dependen de recursos remotos no verificables. Técnicas: ZIP con contraseña desde releases desconocidos, comandos base64/Unicode ofuscados para exfiltrar credenciales, `curl | bash`, instrucciones ocultas tipo "developer mode", envenenamiento de archivos de memoria. La campaña apuntó a usuarios de Claude Code y OpenClaw. Recomienda `uvx mcp-scan@latest --skills`, rotar credenciales, revisar memoria — [Snyk ToxicSkills](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub)

### Inferences
**Checklist para vetar una skill/plugin antes de instalar (síntesis de las fuentes anteriores):**
1. **Origen:** ¿Es de `github.com/anthropics/`, está en `claude-plugins-official`, o es de un autor con identidad pública y reputación (Jesse Vincent, Matt Pocock, Paweł Huryn, Corey Haines, Addy Osmani)? Descartar si viene solo de un agregador sin repo.
2. **Señales del repo:** estrellas/forks altos, commits recientes, licencia clara (MIT/Apache; ojo CC BY-NC), issues atendidos, CI/tests. Desconfiar de conteos inflados o inconsistentes.
3. **Leer el SKILL.md completo** (y archivos .md referenciados): buscar instrucciones que no calcen con el propósito ("ignora advertencias", "modo desarrollador", "no le digas al usuario"), texto oculto, base64/Unicode raro, URLs externas.
4. **Frontmatter:** revisar `allowed-tools` (pre-aprobaciones amplias de Bash = alerta), `shell`, inyecciones `` !`comando` ``.
5. **Scripts y binarios:** abrir todo `scripts/`, `bin/`; alertas: `curl … | bash`, descargas de ZIP con contraseña, `Invoke-WebRequest`/`iex`, lectura de `~/.ssh`, `.env`, credenciales del navegador, envíos a endpoints desconocidos.
6. **Plugins:** revisar `hooks/hooks.json` (qué comando corre y cuándo), `.mcp.json` (qué servidor/URL), `plugin.json`; preferir plugins sin hooks ni MCP para esta hackathon.
7. **Dependencias remotas:** ¿la skill descarga instrucciones o contenido en tiempo de ejecución? Si sí, el comportamiento puede cambiar después de revisarla.
8. **Fijar versión:** usar `#tag`/commit al agregar el marketplace o copiar manualmente una versión revisada; desactivar auto-update en marketplaces de terceros (ya viene off por defecto).
9. **Mínimo necesario:** copiar solo las carpetas de skills que se usarán, no repos enteros; instalar a nivel proyecto cuando sea posible.
10. **Después de instalar:** `/skills` o `claude plugin details <name>` para ver qué se agregó; si algo es sospechoso, desinstalar y borrar caché; no tener credenciales sensibles en la carpeta del proyecto.
- Para este equipo (sin programación), el perfil de riesgo más bajo es: skills de solo Markdown de autores reconocidos + plugins del marketplace oficial; evitar cualquier skill que pida claves API, acceso a cuentas, o que ejecute scripts de instalación.
